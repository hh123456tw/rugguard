# RugGuard 量化系統規劃

目標：從「新幣避雷工具」走到「自己的量化系統」。每一階段都有**過關條件**，沒過就不進下一階段——尤其是用真錢之前。

## 目前進度（2026-10-22）

| 項目 | 狀態 |
|---|---|
| 蒐集程式 24h 不中斷 | ✅ 工作排程 + 看門程式（電腦需不睡眠） |
| 舊資料逐筆價格回補 | ⏳ 背景執行中，約 10 小時 |
| 新特徵（LP 事件、流動性、持有人集中度、創建者歷史） | ✅ 已上線，只有新資料有 |
| 時間外驗證（walk-forward） | ✅ |
| 回測信賴區間 | ✅ |
| 紙上交易 | ✅ 隨蒐集程式運作 |
| 每週自動重訓（較差不覆蓋） | ✅ |
| 鏈設定抽出 | ✅ 目前只有 BSC |
| 小額實盤 | ⛔ 等回測與紙上交易都過關，且由使用者自己操作 |

**目前的模型結論（時間外驗證，修正資料錯誤後）**：rug AUC 0.68、win AUC 0.65；能買分數前 10% 的 2 倍率 6%，
整體基準 8%——**挑幣能力等於沒有**。win 樣本只有 36 筆，需等新特徵與新資料累積後重評。

## 系統架構

```
資料層        掃描器 → 延遲評估 → SQLite（tokens / price_path）
特徵層        GoPlus + 早期買家 + （待加）創建者歷史、資金來源、LP 事件
模型層        LightGBM 多分類（rug/normal/win）→ 風險分數 / 能買分數
策略層        進場條件（能買分數門檻）+ 停利 / 停損 / 時間停損
驗證層        回測（扣費）→ 紙上交易（即時、不花錢）→ 小額實盤
執行層        報價模擬 → 下單 → 出場監控（實盤由使用者自己操作）
風控層        單筆上限、每日虧損上限、同時持倉上限、緊急停止
監控層        儀表板、Telegram、模型漂移、每週重訓
```

## 舊資料回補

`python -m rugguard.backfill` 用 bloXroute 公開節點（`bsc.rpc.blxrbdn.com`，免費、可查歷史 log）抓舊代幣進場後 24h 的**逐筆** Sync 價格。
限制：每次最多 5000 塊、約 15 秒；8 條平行 ≈ 一個代幣 1-2 分鐘，511 個舊代幣約 10 小時。可中斷、重跑會接著做。

實測其他免費節點（2026-10）：publicnode 只給近期、1rpc 每次 50 塊、ankr 需金鑰、官方 dataseed 限流。

更大規模（幾個月的新交易對）也做得到，但只能用鏈上 log 算的特徵（早期買家、LP 事件、價格路徑、創建者歷史）；
**GoPlus 查不到「當時」的安全資料**，現在查會拿到之後的狀態（資料洩漏）。需要有金鑰的 RPC 或資料平台（Dune、BigQuery、Allium）才跑得動。

## 階段

### 階段 0：資料（現在 → 1-2 週）
- 蒐集程式 24 小時不中斷：放到不關機的電腦或 VPS，用工作排程器開機自動啟動、掛掉自動重啟。
- 申請有 `eth_getLogs` 的 RPC 金鑰（NodeReal / Ankr / QuickNode 免費或付費方案）：
  - 回補舊資料的逐筆價格路徑
  - 取樣從每 1-2 分鐘改成逐筆交易
- **過關條件**：>= 2000 筆有交易的 v2 標籤資料、其中 win >= 200 筆。

### 階段 1：研究（資料夠後 1-2 週）
- 跑停利 / 停損回測，選出策略參數。
- 加特徵（依 docs/research-sota.md 的投入產出排序）：創建者錢包歷史、早期買家資金來源聚類、LP 加入 / 撤出 / 鎖倉事件、持有人集中度。
- 驗證一律**依時間切**（walk-forward）：用前幾天訓練、後一天測試，滾動前進。
- 加 TabPFN 當對照模型。
- **過關條件**：時間外資料上，扣手續費、買賣稅、滑價後的平均報酬 > 1.0，且 bootstrap 95% 信賴區間下界 > 1.0。

### 階段 2：紙上交易（2-4 週）
- 寫 paper broker：訊號出現時用 `eth_call` 模擬實際買入（router `getAmountsOut`）與**立刻賣出**（抓 honeypot / 隱藏賣稅），記錄假想成交價。
- 依策略即時監控出場，記錄每筆損益。
- **過關條件**：紙上交易報酬與回測一致（差距在信賴區間內），且期望值仍 > 1.0。

### 階段 3：小額實盤（使用者自己操作）
- 專用熱錢包，只放願意全部損失的金額；私鑰只在使用者電腦上，不進 repo、不給任何人。
- 用私有交易通道（防三明治攻擊）。
- 硬性風控：單筆金額上限、每日虧損上限、同時持倉上限、一鍵停止。
- **過關條件**：實盤損益與紙上交易一致。不一致就退回階段 2 查原因（通常是滑價、MEV、honeypot）。

### 階段 4：擴展到其他鏈

先把鏈相關的設定抽成一份設定檔，其餘程式共用：

| 鏈 | DEX | 改動量 |
|---|---|---|
| Ethereum / Base / Arbitrum 等 EVM | Uniswap v2 系 fork | 小：factory 地址、包裝原生幣（WETH）、出塊時間、GoPlus chain id |
| 同上 | Uniswap v3 / v4、Aerodrome | 中：池子事件與價格算法不同（tick / sqrtPrice） |
| Solana | pump.fun、Raydium | 大：非 EVM，掃描、價格、帳戶模型全部重寫 |

建議順序：BSC 跑通全流程 → 同為 v2 fork 的 EVM 鏈 → v3 類池子 → Solana。
每條鏈的模型分開訓練（行為差很多），共用特徵定義與回測框架。

### 階段 5：營運
- 每週用新資料重訓，監控特徵分布與命中率漂移。
- 儀表板加損益曲線、回撤、每筆交易紀錄。

## 主要風險

- 證據顯示新幣整體是負期望值，利潤集中在發幣者、狙擊機器人、最早出場的人；系統很可能在階段 1 就證明「找幣買」不賺錢，那時應該接受結果。
- 標籤用 24h 單點價格，看不到中途的機會與風險；有價格路徑後應改用策略報酬當標籤。
- 公開 RPC 有頻率限制，資料可能有缺口。
